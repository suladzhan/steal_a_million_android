Реестр отражает факт, а не намерение: если статус `Generated`, значит `meshy make`/`create` уже выполнен и есть task ID. Формат имён файлов и папок: [GENERATION_WORKFLOW.md](GENERATION_WORKFLOW.md). Обязательные проверки перед `Approved`: [QA_CHECKLIST.md](QA_CHECKLIST.md). Правила импорта: [UNITY_IMPORT.md](UNITY_IMPORT.md).

## Поля карточки

| Поле | Значение |
|---|---|
| Asset ID | Runtime/production ID, например `CHAR_runner`, `ANIM_run`, `GATE_frame`, `UI_shield` |
| Статус | `Planned` / `Referenced` / `Generated` / `Exported` / `Approved` / `Rejected` |
| Источник референса | Grok / ручная модель / существующий `GameArt` / внешний источник с указанием лицензии |
| Промпт | Точный текст, отправленный генератору (или ссылка на секцию в [ART_DIRECTION.md](ART_DIRECTION.md) / [CHARACTERS_AND_ANIMATIONS.md](CHARACTERS_AND_ANIMATIONS.md) / [WORLDS_AND_PROPS.md](WORLDS_AND_PROPS.md), если использован каталожный промпт без изменений) |
| Генератор / версия | Grok / Meshy + версия CLI, дата |
| Task ID / resource ID | ID задачи Meshy для повторного `wait`/скачивания |
| Дата | Дата генерации в формате ГГГГ-ММ-ДД |
| Лицензия | Условия использования исходного референса и результата генерации |
| Потрачено credits | Фактическое `consumed_credits`; `Unknown`, если поле не вернулось - никогда не `0` по умолчанию |
| QA | Ссылка/дата прохождения [QA_CHECKLIST.md](QA_CHECKLIST.md), либо `Not started` |
| Путь | Расположение в `01_References` / `02_Generated` / `03_Blender` / `04_Exports` / `05_Approved` |
| Примечание | Известные ограничения, отклонения от каталога, причина Rejected |

## Как вести реестр

1. Запись создаётся на шаге 3 производственного цикла ([GENERATION_WORKFLOW.md](GENERATION_WORKFLOW.md)) - сразу после сохранения референса в `01_References/<ID>/`, со статусом `Referenced`.
2. После отправки в Meshy статус меняется на `Generated`, добавляются task ID и потраченные credits.
3. После исправления в Blender и экспорта в `04_Exports/<ID>/` статус - `Exported`.
4. После прохождения [QA_CHECKLIST.md](QA_CHECKLIST.md) и переноса в `05_Approved/<ID>/` статус - `Approved`, заполняется поле QA.
5. Если ассет не прошёл проверку, статус - `Rejected`, причина - в примечании; новая попытка получает новую запись с тем же Asset ID и следующим номером версии, старая запись не удаляется.
6. Один Asset ID - одна активная строка `Approved`. Более старые версии того же ID помечаются в примечании как заменённые, не удаляются из истории.
7. Runtime ID (`runner`, `vault_diamond`, `Shield` и другие из `shop.json`/`RunnerData.cs`) не переименовываются и не удаляются из реестра: они уже есть в сохранениях игроков.
