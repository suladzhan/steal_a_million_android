# Как мы производим ассеты

## Разделение работы

| Кто / инструмент | Задача | Не считать результатом |
|---|---|---|
| Пользователь + Grok | Референс персонажа, предмета, иконки, внешний вид миров | Скриншот со всем UI не является набором готовых ассетов |
| Ассистент + Meshy | Модель из согласованного референса, текстурирование, при необходимости rig/клипы | Отправленная задача ещё не готовый файл |
| Blender | Исправление геометрии, UV, общего рига, pivot, масштаба, экспорт FBX | Красивый рендер не доказывает корректность сетки |
| Ассистент + Unity | Материалы, prefab-визуалы, Animator, UI, эффекты, проверки Android | Успешная компиляция не доказывает правильную отрисовку |

Grok-видео можно использовать как образец движения, но MP4 не заменяет FBX-анимацию со скелетом. Meshy не должен генерировать всю трассу и персонажа одним объектом.

## Команды проверки установленного CLI

Эти команды проверяют окружение и доступ. Выполняются по одной, с чтением результата. Здесь нет автоматического платного пакетного запуска.

```powershell
node --version
meshy.cmd doctor --output-schema v1 --format json --no-update-check
meshy.cmd auth status --format json --no-update-check
```

Проверить стандартные адреса API `api.meshy.ai` и браузерной авторизации `www.meshy.ai`. Не заменять неизвестный custom host автоматически. Если авторизация уже `authenticated=true` и `verified=true`, использовать её. Если креденшел есть, но проверка не удалась, сначала разобраться с сетью/ошибкой, а не удалять его.

Если авторизации нет, ассистент запускает одну ожидающую команду:

```powershell
meshy.cmd auth login --device --format json --no-update-check
```

Ссылка и пользовательский код показываются в текущем чате; пользователь подтверждает вход в браузере. Ассистент ждёт тот же процесс, затем повторяет `auth status`. Не копировать credential-файл и не показывать bearer device_code. Подключение плагина само по себе не доказывает авторизацию CLI.

## Один производственный цикл

1. Выбрать один ID из каталога и проверить, нет ли уже подходящего результата.
2. Создать/выбрать референс в Grok. Для персонажа сначала A-pose, не бег. Один объект, весь силуэт, без текста.
3. Поместить исходник в `01_References/<ID>/`; сохранить точный промпт, дату, выбранную модель генератора и происхождение входного изображения.
4. Проверить стиль, конечности, палитру и вид сзади. Не отправлять дефектный concept в 3D.
5. Определить минимальную цепочку Meshy. Для first pilot: один персонаж, геометрия и текстура; rig после проверки модели. Не запускать десять скинов сразу.
6. Проверить баланс и оценку стоимости. Покупка кредитов, подписка, новый платный этап и повторная генерация требуют согласования.
7. Отправить `create --async` один раз. Сразу сохранить ресурс и task ID, завести CLI project, ждать тем же resource через `wait`.
8. Скачать модель и доступный thumbnail в `02_Generated/<ID>/`. Просмотреть thumbnail, но не утверждать по нему, что topology и rig исправны.
9. Исправить в Blender, создать экспорт в `04_Exports/<ID>/`, выполнить [проверку](QA_CHECKLIST.md).
10. Согласованный экспорт, provenance и результаты проверки поместить в `05_Approved/<ID>/`. Лишь потом отдельный небольшой импорт в Unity.

## Затраты

До генерации `balance` сообщает остаток, а не цену. Для text/image-to-textured-model можно получить локальную оценку `make --dry-run`. Для дополнительных операций сверять [официальную API-цену](https://docs.meshy.ai/en/api/pricing), просмотренную 2026-09-18. Web-app credits и API credits не считать взаимозаменяемыми без проверки аккаунта.

```powershell
meshy.cmd balance --output-schema v1 --format json --no-update-check
meshy.cmd make "One original stylized mobile runner character in A-pose" --dry-run --output-schema v1 --format json --no-update-check
```

В карточке задачи фиксируются estimate, разрешённый лимит, фактическое `consumed_credits`. Если последнее отсутствует, писать Unknown, не 0. Нет утверждённой сметы для всего каталога. Отдельный костюм, remesh, rerun и дополнительная анимация могут стоить отдельных credits. Сначала подтвердить цену первого ограниченного пакета, затем расходовать только его лимит.

## Параметры будущих задач

Не копировать пример из skill с 4K/30000 faces как мобильный стандарт. Для нас приоритет: цельный low-poly силуэт, 1024 текстура игрока, простой материал. Для image-to-3d доступный режим и polycount уточняются через CLI help. Требования каталога остаются целями, которые проверяются после генерации.

- Для персонажа: `a-pose`, textured result, затем проверка before rig. Перегенерированный скин не получает автоматически тот же скелет.
- Для неподвижного здания: geometry + BaseColor; rig и animation не нужны.
- Для сейфа: корпус, дверь и петля должны быть разделены в Blender. Автоматический humanoid rig здесь не нужен.
- Для другого формата существующей модели: экспорт в Blender либо только conversion, не повторное text-to-3d.
- Для другого LOD: существующая модель и проверенное упрощение, не новая генерация предмета.
- Для анимации: сначала проверить клипы, которые уже вернул rig. Не платить повторно за бег без проверки выдачи.

Workspace всех записывающих CLI-команд: абсолютный `.../AssetProduction/02_Generated`; CLI project root внутри `02_Generated/meshy_output`. Передавать `--workspace` всем записывающим business-командам, `--output-schema v1 --format json --no-update-check` для JSON-вывода. Имена ресурсов и asset keys брать из ответа CLI, не угадывать.

## Ошибки без лишних списаний

Timeout ожидания не означает неудачную генерацию: продолжить `wait` того же task ID. Не повторять create при сетевой неопределённости, пока не найден исходный task. Истёкшая ссылка скачивания требует повторного получения выдачи задачи, а не новой модели. При недостаточном балансе прекратить новые платные запросы, сохранить уже полученные результаты.

## Имена и версии

`<ASSET_ID>__v001__<part>.<ext>`, латиница, без пробелов. Например `CHAR_runner__v001__reference_front.png`, `CHAR_runner__v001__model.fbx`, `CHAR_runner__v001__basecolor.png`, `ANIM_run__v001.fbx`.

В каждой передаваемой папке: модель, используемые текстуры, preview, Markdown-карточка. Для рига дополнительно список костей, исходная поза, клипы. Сохранять `.blend` отдельно от экспортов. Не перезаписывать одобренную версию без нового номера.

Новая модель не переименовывает `runner`, `vault_diamond` или другие runtime ID: они уже находятся в сохранениях игроков.
